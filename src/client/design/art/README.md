## Originals and provenance

The [November 1 supporting-screen boards](../../../../docs/design/concept-direction.md) extend the existing artwork hierarchy without generating or modifying originals. On 2026-11-06 the owner chose to follow the boards’ composition: art that bleeds off page and card edges, depth, the board logo and an invitation landing. The supplied refined boards are stored unchanged under `docs/design/concepts/2026-11-01/` and are not imported by the client.

`hero-rose.webp` (936 × 378) and the three position plates (121 px tall; 209, 236 and 224 px wide) are the transparent originals added on 2026-10-27. They ship as they are. The ribbon (2172 × 724), account sprig (1945 × 809) and three-card spread (1983 × 793) were made with built-in ImageGen on 2026-10-31 from the owner's supplied concepts. The dedicated mobile corner (1222 × 1287) was generated the same day from the ribbon/sprig style references as a new compact three-leaf composition, not a tiny ribbon or a crop. They retain the cream, sage, teal and coral botanical print language. All four originals are untouched RGBA PNGs with transparent pixels and are retained here for future exports; runtime code imports only the delivery variants.

All decorative `Art` images have `alt=""`, `aria-hidden="true"` and intrinsic dimensions. Art in a slot beside a heading keeps reserved layout space. Art that bleeds off an edge (the rose, the position plates and the leaf band) is `position: absolute`, has `pointer-events: none` and sits behind content. It never covers text or controls at 320 px or at 400% zoom, and it is hidden in forced-colors mode. Actual photographs always have descriptive alternative text. The illustrative synthetic spread fixture is `tests/fixtures/spread-photo.jpg`, outside the client bundle. It is not card-recognition evidence.

## Lossless delivery variants

`optimized/manifest.json` records original SHA-256, dimensions and bytes, plus every generated variant. `Art` uses width-descriptor `srcset`, placement-specific `sizes` and a media-qualified desktop `<picture>` source with the compact mobile image as fallback. This also avoids WebKit speculatively fetching desktop ribbon/sprig candidates while React mounts the picture tree. No full-resolution PNG ribbon, sprig, spread or corner is imported into the production bundle.

| Image             | Original bytes | Widths → lossless WebP bytes              |
| ----------------- | -------------: | ----------------------------------------- |
| Ribbon            |      1,196,767 | 320 → 27,476; 640 → 85,660; 960 → 178,842 |
| Account sprig     |      1,274,288 | 160 → 10,960; 320 → 33,300; 560 → 86,404  |
| Three-card spread |      1,875,484 | 320 → 49,364; 640 → 160,384               |
| Mobile corner     |      1,257,168 | 80 → 7,134; 160 → 21,638; 240 → 42,886    |

The leaf band uses the 960 px ribbon variant as a CSS background. The rose ships as its original 137,080-byte WebP, and the plates as their original PNGs (43,360–47,043 bytes). The rose is 936 px wide, so it renders soft on high-density screens at 46rem; a 2× export is a follow-up.

For these decorations alone, the mobile empty form at DPR 1 selects about **56.5 kB instead of 3.07 MB** (98.2% less); at DPR 2, about **182 kB** (94.1% less). Account's mobile decoration selects 7.1 kB at DPR 1 instead of 1.27 MB. These are selected-asset byte comparisons, not total page-weight claims. `sizes` choices are also recorded by the browser matrix.

Rebuild using Python 3 with Pillow installed:

```sh
python3 scripts/optimize-illustrations.py
```

This is a development-only tool, not an application dependency. It resizes from the originals with Lanczos, encodes lossless RGBA WebP, then verifies a byte-for-byte RGBA round trip against each resized source, including partially transparent edges. There is no JPEG matte, alpha removal or lossy color encoding. The 1×/2× exports cover the actual CSS slots; the corner also has a 3× option. Inspect both themes at actual display sizes after regenerating.

Palette decision: the owner-approved Reflection Paper and Evening palette supersedes Solstice. All eight exact hex values and semantic mappings live in `design/tokens.css`; see the [implementation guide](../../../../docs/design/reflection-system.md). Pastel UI surfaces use Ink text; illustration originals retain their existing colors.

`spiral-bloom.svg` is an export from the [Reflection Figma library](https://www.figma.com/design/a0u0Ok74iKTMjp1L5osRnU?node-id=3-174), with its geometry and intrinsic proportions preserved and a descriptive title added. `return-mark-paper.svg` and `return-mark-evening.svg` keep their file names and 30 px size but were redrawn on 2026-11-06 to match the header logos on boards 01 and 03: a Teal disc with a Paper and Mint center (37% of the diameter, inside a thin Paper ring), and a Paper and Mint disc around an Evening center. The Figma library still has the earlier ring mark. All three ship locally and are decorative in the app.
