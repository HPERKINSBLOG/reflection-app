# Milestone 3 continuity implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a person deliberately share bounded excerpts and ask a follow-up about an exact saved edition, while preserving export, deletion, recovery and existing readings.

**Architecture:** Add revision-bound context services to the existing Worker and a separately versioned continuity writer to the existing request lifecycle. Under proposed decision D1, a follow-up adds an immutable edition to the parent's saved session; it does not create an independently retained child. Complete every private-copy lifecycle before exposing creation routes.

**Tech Stack:** Node 26, TypeScript, React, Hono, Zod, Cloudflare D1/R2, Vitest/workerd and Playwright; existing dependencies only.

**Spec:** [Milestone 3 preparation](../../MILESTONE_3_PREPARATION.md), [selected context](../../design/selected-context.md), [generation](../../architecture/GENERATION.md). The preparation's decision register identifies unresolved older proposals; it does not convert recommendations into owner approvals. Reviewed 2026-11-02. All tasks below are unimplemented.

## Global Constraints

- Preserve the existing dirty working tree. Review an explicit file allowlist before any checkpoint; no broad staging, reset, cleanup, publication or deployment is part of this plan preparation.
- D1 is awaiting clarification. Its proposed shared-retention behavior governs this draft; resolve it before C4 changes storage or UI promises. C1–C3 privacy and selection work can proceed independently.
- Use at most 3 distinct grants, 1,200 Unicode code points per excerpt and 3,000 total; no silent truncation. Offsets are code points, not UTF-16 code units or grapheme clusters.
- Keep current question limits, English confirmation, quotas, idempotency, authentication epochs, CSRF, CAS, recovery acknowledgement and account fences. No implicit sharing of notes, reflections, stance, photos, filenames or history.
- Grant eligibility, complete request preview, request acknowledgement and general AI permission are separate. Revocation blocks future use; it cannot retract a payload already sent.
- Every new private copy participates in encryption/AAD, 20 MiB account admission, at least 1 KiB per owned row, export, erasure, rekey and restore replay.
- Reuse Paper `#F7F3E8`, Ink `#103F46`, Teal `#126F73`, Evening `#082F33`, Mint `#A8D5BA`, Coral `#F28B7B`, Butter `#F1D27B`, Sage `#A9B88F`; Newsreader headings, Figtree body and Outfit brand. Use existing design components and in-memory private drafts.
- Preserve historical v1/v2 decoding. New continuity live dispatch requires separate policy/corpus qualification; local synthetic development does not require production qualification, human approval, age or geography gates.
- New migrations follow `0017_revisit_notes.sql`; reserve `0018_context_continuity.sql` only if still available at execution time. Never edit an applied migration.

## Review Focus

1. Emoji/combining text and forged offsets: exact reviewed code points must reach the writer without splitting a surrogate pair or substituting text. Pin in C1/C3.
2. Source revision changes between preview, dispatch and publication: no stale or unacknowledged fragment may escape, even when the original row is gone. Pin in C2/C4.
3. Two tabs start follow-ups while a deletion or source withdrawal races: one durable dispatch per request, distinct edition numbers and no resurrection. Pin in C4.
4. Recovery, AI-off or account capacity occurs with copied context present: owned read/export/delete remain available; restore revokes permission and never resends. Pin in C2/C5.
5. Keyboard/reload/offline flows lose an acknowledgement or selected range: never silently reselect, duplicate a request or discard an unsaved question on a recoverable conflict. Pin in C3/C4/C5.

## File boundaries

`src/contracts/context-policy.ts` owns code-point bounds; `src/worker/readings/context.ts` owns authenticated grants and preview resolution. `src/domain/tarot/continuity.ts`, `writer-v3.ts` and `safety-v3.ts` own the new immutable plan, outbound projection and candidate checks. `src/client/context-selection.tsx` and `follow-up.tsx` own the new interactions. Existing export, erasure, request, recovery and component modules remain the integration points; do not introduce a second lifecycle engine.

New names and signatures below are the proposed implementation contract, not claims that these exports already exist. Use `z.infer<typeof Schema>` for existing Zod types and the Worker `Session` from `src/worker/identity/types.ts`. Keep public `Principal` service interfaces as contract projections; do not substitute them for authenticated Worker sessions.
